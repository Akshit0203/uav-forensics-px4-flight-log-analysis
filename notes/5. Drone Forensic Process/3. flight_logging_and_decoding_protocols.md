
# Flight Logging & Decoding Protocols

---

## Data Logging — The Drone "Black Box"

Flight controllers log data not for forensic purposes but for **system diagnostics and troubleshooting**. If a drone doesn't fly properly, logs help the manufacturer diagnose the issue. Forensic analysts take advantage of this — you will find data logging capabilities in almost every drone.

| Aspect | Detail |
|--------|--------|
| **Built-in logging** | Most flight controllers (e.g., PixHawk) have data logging included |
| **External logging** | Some controllers (e.g., DJI Naza) require an off-board data logger |
| **GCS logging** | Some Ground Control Station apps also log flight data |
| **DJI Phantom 3 series** | Professional, Advanced, and Standard all create very similar logs |

### DJI Log File Types

| Source | Filename Format | Description |
|--------|----------------|-------------|
| **UAV Flight Data Recorder** | `FLY???.DAT` | On-board logs; `???` = three-digit sequence number (e.g., `FLY688.DAT`, `FLY051.DAT`) |
| **GCS / DJI GO App** | `DJIFlightRecord_<date/time>.TXT` | Logs retrieved from the mobile device running DJI Go |

- All logs contain precise **date and time stamps**
- Finding `FLYxxx.DAT` files in memory is a **classic signature** confirming DJI log files

## FLY???.DAT — Extraction & Analysis

### Physical Location

- Stored on a **4 GB microSD card** on the bottom side of the Main Board inside the UAV
- The UAV automatically **pushes out the oldest `.DAT` files** to make room for the newest (FIFO overwrite)
- To remove the card, the UAV casing **must be opened**

![](attachments/Pasted%20image%2020260706190810.png)

### Extraction Procedure

1. Carefully remove hot-melt glue or casing, open the slot, and **extract the microSD card**
2. **Create a forensic image immediately** — open **FTK Imager** and create a bit-stream master image of the microSD card
3. Make a **working copy** of that image on a USB drive or other storage media
4. Load the working copy into **Autopsy** to extract deleted files and media
5. Focus on extracting the `.dat` files with the **most recent timestamps**

> [!CAUTION] Never Work on the Original
> Do not perform any extraction directly on the raw card. Do not connect it directly to Autopsy. Always image first, then work on the copy.

### Decoding with DatCon

Use **DatCon.exe** — a free application by Rowland Johnson: https://datfile.net

DatCon extracts a mountain of information, primarily flight data:
- **GPS coordinates**
- **Battery metrics**
- **Motor states** (on/off, RPM)
- **Flight altitude**
- DatCon is specifically designed to assist in **crash cause determination**

> [!NOTE] Reference Frameworks
> - **NIST framework** for digital forensics
> - VTOLabs.com/drone-forensic

### Chinese Data Upload Concern

> [!WARNING] Forced Log Upload to Chinese Servers
> Many Chinese drone companies write their software so that the moment you open their app, you are forced to agree to upload all flight logs to servers in China. In the case of DJI, logs are synced to Chinese servers to analyze crash data and improve products. This is also observed with 3D printers like Bambu Lab, where STL files are sent to Chinese servers — both for data collection and to train their AI models on market trends.

## Drone Log Data Analysis

Drone log analysis involves extracting, decoding, and interpreting flight data from the drone's:
- **Internal storage** — typically ~28 MB of flash memory reserved for firmware and basic settings
- **Onboard SD card**
- **Mobile app** — if the drone was connected to a mobile device

This data is critical for:
- **Troubleshooting crashes**
- **Tuning flight performance** — using the PID (Proportional-Integral-Derivative) control system to stabilize flight
- **Verifying autonomous missions**

### Key Analysis Tools by Firmware

The tool you use depends entirely on your drone's firmware and log file format:

| Firmware | Log Format | Analysis Tool | Type | Notes |
|----------|-----------|---------------|------|-------|
| **ArduPilot** | `.bin` / `.log` | **Mission Planner** (built-in analyzer) | Desktop | Upload logs directly for analysis |
| **ArduPilot** | `.bin` / `.log` | **UAV Log Viewer** | Web-based | Community-developed; auto-plots flight path, motor speeds, altitude |
| **PX4** | PX4 logs | **PX4 Flight Review** | Web-based | Generates automated comprehensive system health reports |
| **PX4** | PX4 logs | **PlotJuggler** | Desktop | Offline desktop analysis alternative |
| **Any / Custom** | Any format | **MATLAB Flight Log Analyzer** | Desktop | Deep signal processing; requires MATLAB knowledge |
| **Multi-platform** | Various | **TIPlot** | Desktop | 3D trajectory tracking, cross-platform compatibility |

> [!TIP] Quick Reference
> - **DJI logs** → `.dat` / `.txt` format → use **DatCon**
> - **ArduPilot logs** → `.bin` / `.log` format → use **Mission Planner** or **UAV Log Viewer**
> - **PX4 logs** → use **Flight Review** (web) or **PlotJuggler** (desktop)
> - **Custom / any format** → use **MATLAB** or **TIPlot**

> [!IMPORTANT] The Software Plots — You Infer
> Although the software plots graphs and presents curves, the **final inference must be drawn by you**. The system displays the data, but establishing the logical connection and correlating the evidence to your specific case is the real work of forensic reporting.
