# Memory Forensics & Digital Forensic Process

---

# 1. Memory Forensics

## What is Memory Forensics?

**Memory forensics** (or memory analysis) is a subset of digital forensics that focuses specifically on **volatile data** — analyzing a computer's memory dump (core dump), which is a snapshot capture of memory data at a specific instant.

| Scope | Covers |
|---|---|
| **Digital Forensics** | All storage media — RAM, ROM, SD cards, hard drives, optical drives |
| **Memory Forensics** | Specifically **volatile data** (RAM) |

## What Volatile Data Contains (Drone Context)

| Data Type | Examples |
|---|---|
| **Mission history** | Waypoints, flight path calculations |
| **Messages** | Communications between transmitter and receiver |
| **Crash reports** | Error logs from the flight controller |
| **Logs** | Runtime system activity logs |
| **Configuration** | System settings, flight mode configs |
| **Open network connections** | GPS module, camera, LiDAR, and sensor communications over internal network |
| **Recently executed commands** | Last processes and instructions run by the FC |

## Why Memory Forensics Matters

- Provides **unique insights into runtime system activity** — what the drone was doing at the moment of capture.
- Configuration analysis can reveal the drone was set up for a **much longer mission** than the one it was on (key forensic context).
- **Open network connections** from internal peripherals (GPS, cameras, LiDAR) can be extracted.

## Critical Procedure: Core Dump

> ⚠️ **When a drone crashes, the battery typically disconnects, depowering the system and losing all volatile data.**

If you recover a drone that is **still powered on** (even if propellers aren't spinning):

1. **Immediately take a core dump** (full memory dump of RAM + system).
2. Perform this **in front of the person** who brought the artifact.
3. **Video-record the entire process** for chain of custody.

> This is your only chance to capture volatile data — once power is lost, it's gone.

# 2. Digital Forensic Process

![](attachments/Pasted%20image%2020260706151427.png)

## The 4 Stages

### Stage 1: Investigation Preparation

- Identify the **purpose** of the investigation and **resources required**.
- Determine the type of incident.
- Ensure you have the **right tools** for the specific drone platform:

| Drone Platform | Required Tools |
|---|---|
| **DJI** | DJI-specific firmware tools |
| **Betaflight** | Betaflight Blackbox Explorer, configurator |
| **Pixhawk / ArduPilot** | Mission Planner, QGroundControl |

### Stage 2: Evidence Acquisition

- Carefully **identify the source** of digital evidence.
- **Preserve** the evidence — start the chain of custody form immediately.
- **Image** the storage devices (create forensic copies).

> ⚠️ **Analysis is NEVER performed on the original artifact.** Always image the storage device and work on the copy — never on the master.

### Stage 3: Evidence Analysis

- Identify tools and techniques to be used.
- Brainstorm and create a flow diagram.
- Process the data and interpret analysis results.
- Search for potential evidence in recovered data.

> This is like looking for a needle in a haystack. ~90% of cases are routine, but individual effort and engineering make the difference.

### Stage 4: Results Presentation

- Draft a **comprehensive report** of findings.
- Document facts and summarize evidence.
- Prepare for **court testimony**.

> **Government of India mandate:** Forensic labs must preserve all evidence for **3–5 years**, depending on priority level.

# 3. Chain of Custody (CoC)

> **"A chain of custody is the process of validating how any kind of evidence has been gathered, tracked, and protected on its way to a court of law. If you don't have a chain of custody, the evidence is worthless."**

## The 6 Critical Questions

| Question | What It Documents |
|---|---|
| **What** is the evidence? | Detailed description (FC serial number, branded markings, outer casing) |
| **How** did you get it? | Acquisition method and circumstances |
| **When** was it collected? | Initial custody date and time |
| **Who** has handled it? | Every person who touched the evidence, with signatures |
| **Why** did that person handle it? | Reason for each transfer (forensic analysis, imaging, etc.) |
| **Where** has it traveled? | Every location, including lab and final secure storage |

## Chain of Custody Record Sheet

![](attachments/Pasted%20image%2020260706151747.png)

### What the Record Includes

- **Case number** and title
- **Evidence description** (for drones: FC serial number, branded markings on outer casing)
- **Initial custody date** and laboratory location
- **Transfer details:** date, reason for transfer, signatures of both parties (handover + receiver)
- **Witness signature** — essential for court admissibility
- **Final custody** documentation

> Without a proper chain of custody, opposing counsel will argue evidence was **tampered with**, and it will be thrown out of court.

# 4. Acquisition Process — Imaging & Integrity

![](attachments/Pasted%20image%2020260706152523.png)

## Imaging Workflow

1. Create a **master copy** (forensic image) of the storage media.
2. Work **only on the copy** — never the original.
3. Verify integrity using **cryptographic hashes**.

> ⚠️ **Hashes must match at all times.** If the hash of the copy does not match the hash of the original, the evidence will be thrown out of court.

## Write-Blocker

![](attachments/Pasted%20image%2020260706152634.png)

A **write-blocker** is an essential instrument for physical imaging. It ensures that **not a single bit of data** can travel back to alter the original evidence.

> Open-source tools are available to perform forensic imaging.

# Exam / Interview Points

### Memory Forensics
- **Memory forensics** = analysis of volatile data (RAM snapshot / core dump)
- Volatile data: mission history, messages, crash reports, logs, configs, open connections
- Drone crash → battery disconnects → **volatile data lost** (capture immediately if powered on)
- Always **video-record** the core dump process + do it in front of the evidence provider

### Forensic Process (4 Stages)
1. **Preparation** — identify purpose, resources, correct tools for platform
2. **Acquisition** — preserve evidence, start CoC, image storage (never analyze originals)
3. **Analysis** — process data, search for evidence (needle in a haystack)
4. **Presentation** — comprehensive report, court testimony

### Chain of Custody
- **No CoC = evidence is legally worthless**
- 6 questions: What, How, When, Who, Why, Where
- Must include: case number, evidence description, transfer dates, signatures, **witness signature**
- India: evidence preserved **3–5 years**

### Imaging & Integrity
- Always create a **forensic copy** → work on the copy
- **Hash verification** must match at all times — mismatch = evidence thrown out
- **Write-blocker** = prevents any data from being written back to the original
- Open-source imaging tools available
